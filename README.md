# 📷 구글 드라이브 사진 업로더 (GitHub Pages + Apps Script)

스마트폰의 사진을 골라서 **구글 드라이브 폴더에 `YYYYMM월` 폴더(예: `202611월`)로 자동 분류해 올리는** 웹 앱입니다.
홈 화면에 아이콘으로 설치해서 앱처럼 쓸 수 있습니다.

## 1. 전체 구조

```
[스마트폰]                         [GitHub Pages]            [Google Apps Script]        [구글 드라이브]
 홈 화면 아이콘  ──열기──▶  index.html (화면)
 사진 선택/체크
 "올리기" ─▶ 폰 임시 저장(IndexedDB)
 Wi‑Fi 연결되면 ──── 사진 1장씩 POST (토큰 포함) ─────────▶  doPost()  ──저장──▶  루트폴더/202611월/사진.jpg
                     ◀──────────── 결과(업로드/중복/오류) ──────────────┘
```

- **화면(HTML)** 은 GitHub Pages가 제공합니다. 무료이고 아이콘·설치(PWA)를 지원합니다.
- **업로드 처리**는 Apps Script가 맡습니다. 내 구글 계정 권한으로 드라이브에 저장합니다.
- 둘은 **웹 앱 URL + 비밀 토큰**으로 연결됩니다. 이 두 값은 폰 브라우저에만 저장되고 GitHub에는 올라가지 않습니다.

## 2. 준비물

| 항목 | 설명 |
|---|---|
| 구글 계정 | 드라이브 폴더 소유자(또는 편집 권한자). Apps Script를 이 계정으로 배포합니다. |
| 드라이브 폴더 ID | 업로드할 최상위 폴더. 폴더를 열었을 때 주소 `drive.google.com/drive/folders/`**`여기`** 가 ID입니다. (`Code.gs`에 이미 입력되어 있음) |
| GitHub 계정 | 무료 계정이면 충분합니다. |
| 스마트폰 | 안드로이드(삼성 인터넷/크롬) 권장. 아이폰(사파리)도 사용 가능하지만 Wi‑Fi 자동 판별이 안 됩니다. |

## 3. 파일 구성

### GitHub 저장소에 올리는 파일 (8개)
| 파일 | 역할 |
|---|---|
| `index.html` | 앱 화면과 동작 전체 (갤러리, 선택, 임시 저장, 업로드) |
| `manifest.webmanifest` | 홈 화면 설치 정보 (앱 이름, 아이콘, 색상) |
| `sw.js` | 서비스 워커 — 화면 파일을 폰에 캐시해 설치형 앱처럼 동작 |
| `icon-192.png` · `icon-512.png` | 일반 아이콘 (둥근 모서리) |
| `icon-maskable-512.png` | 폰이 모양을 잘라 쓰는 꽉 찬 아이콘 |
| `apple-touch-icon.png` | 아이폰/삼성 인터넷용 홈 화면 아이콘 |
| `README.md` | 이 문서 |

### GitHub에 올리지 **않는** 파일
| 파일 | 어디에 쓰나 |
|---|---|
| `Code.gs` | **Apps Script 편집기**에 붙여넣습니다. ⚠ 비밀 토큰이 적혀 있으므로 공개 저장소에 올리면 안 됩니다. ([12장](#12-보안-주의사항) 참고) |
| `appsscript.json` | Apps Script의 매니페스트 파일에 붙여넣습니다. |

> 예전 `icon.svg`는 더 이상 쓰지 않으니 저장소에 남아 있다면 삭제해도 됩니다.

## 4. 1단계 — Apps Script 백엔드 만들기

### 4-1. 프로젝트 만들기
1. https://script.google.com 접속 (드라이브 폴더 소유 계정으로 로그인)
2. 왼쪽 위 **새 프로젝트** 클릭
3. 프로젝트 이름을 `사진업로더`처럼 알아보기 쉽게 변경

### 4-2. 코드 붙여넣기
1. 편집기의 `코드.gs`(또는 `Code.gs`) 내용을 **전부 지우고**, 제공된 `Code.gs` 전체를 붙여넣습니다.
2. 맨 위 부근의 아래 줄을 찾아 **나만 아는 긴 문자열**로 바꿉니다.
   ```js
   const SECRET_TOKEN = 'CHANGE-ME-TO-YOUR-SECRET';
   ```
   - 영문 대소문자+숫자 조합 20자 이상 권장 (예: `k7Qp2xVn9Lw4TzR8mB3sYd6A`)
   - 따옴표(`'`)는 지우지 마세요.
   - **이 값을 메모해 두세요.** 나중에 폰의 ⚙ 설정에 똑같이 입력해야 합니다.
3. 저장 (Ctrl+S)

### 4-3. 매니페스트(`appsscript.json`) 교체
1. 왼쪽 ⚙ **프로젝트 설정** 클릭
2. "**'appsscript.json' 매니페스트 파일을 편집기에 표시**" 체크
3. 왼쪽 파일 목록에 생긴 `appsscript.json`을 열고 아래 내용으로 교체
   ```json
   {
     "timeZone": "Asia/Seoul",
     "dependencies": {},
     "exceptionLogging": "STACKDRIVER",
     "runtimeVersion": "V8",
     "oauthScopes": ["https://www.googleapis.com/auth/drive"],
     "webapp": { "executeAs": "USER_DEPLOYING", "access": "ANYONE" }
   }
   ```
4. 저장

### 4-4. 드라이브 권한 승인 (최초 1회)
1. 편집기 위쪽 함수 선택 칸에서 **`authorize`** 선택 → **실행**
2. "권한 검토" 창 → 내 계정 선택
3. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (프로젝트 이름)(안전하지 않음)으로 이동 → 허용**
   (내가 만든 스크립트라서 나오는 정상 화면입니다.)
4. 실행 로그에 `접근 가능한 폴더: ○○○` 가 나오면 성공입니다. 오류가 나면 이 계정이 폴더에 접근 권한이 없는 것입니다.

### 4-5. 웹 앱으로 배포
1. 오른쪽 위 **배포 → 새 배포**
2. 톱니바퀴(유형 선택) → **웹 앱**
3. 설정
   - 설명: `v1` (아무거나)
   - 다음 사용자로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
4. **배포** 클릭 → 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사해서 메모

> 이 URL과 4-2의 토큰, 둘 다 있어야 폰에서 사용할 수 있습니다.

## 5. 2단계 — GitHub Pages로 화면 올리기

별도 프로그램(Git) 없이 **웹 브라우저만으로** 할 수 있습니다.

### 5-1. 저장소 만들기
1. https://github.com 로그인 → 오른쪽 위 **+ → New repository**
2. Repository name: `photo-uploader` (원하는 이름 가능, 영문 소문자 권장)
3. **Public** 선택 (무료 계정에서 Pages를 쓰려면 Public이어야 합니다)
4. **Add a README file**은 체크하지 않아도 됩니다 → **Create repository**

### 5-2. 파일 올리기
1. 저장소 화면에서 **uploading an existing file** (또는 Add file → Upload files)
2. [3장](#3-파일-구성)의 **8개 파일**을 한꺼번에 끌어다 놓기
   - `Code.gs`, `appsscript.json`은 **올리지 않습니다.**
3. 아래 **Commit changes** 클릭

### 5-3. Pages 켜기
1. 저장소 **Settings → Pages**
2. **Build and deployment → Source**: `Deploy from a branch`
3. **Branch**: `main` / 폴더 `/ (root)` → **Save**
4. 1~2분 기다린 뒤 페이지를 새로고침하면 위쪽에 주소가 표시됩니다.
   ```
   https://<내 GitHub 아이디>.github.io/photo-uploader/
   ```
5. 이 주소를 PC 브라우저에서 먼저 열어 화면이 나오는지 확인합니다.

## 6. 3단계 — 스마트폰에 설치하고 설정하기

### 6-1. 주소 열기
스마트폰 브라우저에서 위 GitHub Pages 주소를 엽니다.

> ⚠ **반드시 GitHub Pages 주소로 여세요.** `script.google.com/…/exec` 주소로 열면 아이콘이 "G" 글자로 나오고 앱 화면도 제공되지 않습니다.

### 6-2. 서버 연결 설정 (최초 1회)
처음 열면 **⚙ 서버 연결 설정** 창이 자동으로 뜹니다. (나중에 상단 `⚙ 설정` 버튼으로 다시 열 수 있습니다.)
1. **Apps Script 웹 앱 URL**: 4-5에서 복사한 `…/exec` 주소
2. **비밀 토큰**: 4-2에서 정한 `SECRET_TOKEN`과 **완전히 같은** 문자열
3. **연결 테스트** 클릭 → `✅ 연결 성공 — 업로드 폴더: ○○○` 이 나오면 정상
4. **저장**

### 6-3. 홈 화면에 아이콘 추가
| 브라우저 | 방법 |
|---|---|
| 삼성 인터넷 | 메뉴(≡) → **현재 페이지 추가** → **홈 화면** → 이름 확인 → 추가 |
| 크롬(안드로이드) | ⋮ → **홈 화면에 추가** (또는 **앱 설치**) |
| 사파리(아이폰) | 공유 버튼 → **홈 화면에 추가** |

- 아이콘 아래 이름을 바꾸려면 추가할 때 입력 칸에서 수정하거나, `manifest.webmanifest`의 `short_name`을 고칩니다.
- 아이콘을 **바꾼 뒤에는** 기존 아이콘을 삭제하고 다시 추가해야 새 아이콘이 보입니다. (홈 화면 아이콘은 추가하는 순간의 이미지로 고정됩니다.)

## 7. 사용 방법

### 화면 구성
| 위치 | 내용 |
|---|---|
| 맨 위 | 제목, **네트워크 상태 배지**(📶 Wi‑Fi / 📱 모바일 데이터 / ⛔ 오프라인 / ❔ 확인 불가), ⚙ 설정 |
| 도구줄 | `+ 사진 불러오기`, `전체선택`, `선택해제`, 선택 개수 |
| 날짜 칩 | `전체`와 날짜별 버튼(예: `11/10 (23)`) — 누르면 그 날짜만 표시 |
| 가운데 | 날짜별로 묶인 사진 갤러리 |
| 맨 아래 | 업로드 상태, 진행 막대, **올리기** 버튼, 업로드 내역 |

### 업로드 순서
1. **`+ 사진 불러오기`** → 휴대폰 갤러리에서 올릴 사진들을 여러 장 선택
   (웹 앱은 갤러리를 자동으로 읽을 수 없어서, 이렇게 직접 불러오는 방식입니다.)
2. 날짜 칩으로 일자별로 확인
3. 사진 선택 — 세 가지 방법
   - **탭**: 사진을 누르면 선택/해제
   - **체크 후 끌어내리기**: 사진 왼쪽 위 ◯ 체크 표시를 **누른 채 아래(또는 위)로 끌면** 지나간 사진이 한꺼번에 선택됩니다. 이미 선택된 사진에서 시작하면 한꺼번에 해제됩니다. 화면 가장자리로 가면 자동 스크롤됩니다.
   - **날짜 단위**: 날짜 제목 오른쪽 `이 날짜 전체선택`, 또는 위의 `전체선택`
4. **`올리기 (N)`** 클릭
   - 선택한 사진이 먼저 **휴대폰 안에 임시 저장**됩니다.
   - **Wi‑Fi에 연결되어 있으면** 바로 한 장씩 업로드를 시작합니다.
   - Wi‑Fi가 아니면 `Wi‑Fi 연결을 기다리는 중...` 으로 대기하다가, 연결되는 순간 자동으로 올립니다.
5. 하단에서 진행 상황 확인: `완료 · 중복건너뜀 · 오류 · 대기`
6. 끝나면 `✅ 모든 업로드가 끝났습니다.` 표시. 내역은 `업로드 내역 보기`에서 확인합니다.

### 올리기 후에는
- 업로드가 끝난 사진은 갤러리에서 사라집니다(대기열로 이동).
- 오류가 난 사진은 `업로드 내역 보기 → 오류 항목 재시도`로 다시 시도합니다.

## 8. 동작 규칙 상세

### 폴더 분류
- 루트 폴더 아래에 **사진 파일의 수정일 기준** `YYYYMM월` 폴더를 만들어 저장합니다. (예: 2026년 11월 사진 → `202611월`)
- 폴더가 없으면 자동 생성, 있으면 그대로 사용합니다.
- 기준 시간대는 `Asia/Seoul`입니다.
- 기준은 "촬영일"이 아니라 파일의 **수정일**입니다. 카톡·메신저로 받은 사진이나 다른 곳에서 복사한 사진은 받은/복사한 날짜가 수정일이 될 수 있어서, 폴더가 촬영일과 다르게 만들어질 수 있습니다.

### 중복 처리
| 상황 | 결과 |
|---|---|
| 같은 폴더에 **이름과 용량이 같은** 파일이 있음 | **건너뜀** (같은 사진으로 간주) |
| 이름은 같은데 **용량이 다름** | 이름 뒤에 `_1`, `_2`…를 붙여 **저장** |
| 이름이 다름 | 저장 |
- 화면에서도 같은 사진(이름+용량+수정일이 같음)을 두 번 불러오면 한 번만 표시합니다.
- 중복 판단은 **같은 월 폴더 안**에서만 합니다.

### Wi‑Fi 판별
- 브라우저가 연결 종류를 알려주면(주로 안드로이드) Wi‑Fi일 때만 업로드합니다.
- 연결 종류를 알 수 없는 환경(아이폰 사파리, PC, 일부 브라우저)에서는 상단 배지가 `❔ 네트워크 종류 확인 불가`로 표시되고 **업로드가 대기**합니다. 이때는 하단의 **"Wi‑Fi 여부를 확인할 수 없는 기기는 현재 네트워크로 업로드 허용"** 체크를 켜면 올라갑니다. (이 경우 모바일 데이터로도 올라갈 수 있으니 직접 Wi‑Fi 상태를 확인하세요.)

### 임시 저장
- "올리기"를 누르면 사진 파일이 폰 브라우저의 저장소(IndexedDB)에 복사됩니다.
- 앱을 닫거나 폰을 재부팅해도 남아 있고, 다시 열면 자동으로 이어서 올립니다.
- 업로드에 성공한 사진은 임시 저장에서 지워집니다. (원본 사진은 건드리지 않습니다.)
- 브라우저 **사이트 데이터를 삭제**하면 임시 저장분과 ⚙ 설정 값도 함께 지워집니다.

### 업로드가 진행되는 조건
- **앱 화면이 열려 있는 동안** 진행됩니다. 앱을 완전히 닫으면 멈췄다가 다음에 열 때 이어서 올립니다.
- 업로드 중에는 화면이 꺼지지 않도록 요청합니다. (지원하는 브라우저에 한함)
- 한 장씩 순서대로 올립니다.

## 9. 수정·업데이트 방법

| 바꾸는 것 | 방법 |
|---|---|
| **Code.gs 수정** (폴더 ID, 토큰 등) | Apps Script에서 저장 → **배포 → 배포 관리 → ✏ 편집 → 버전: 새 버전 → 배포**. 저장만으로는 반영되지 않습니다. URL은 그대로입니다. |
| **토큰 변경** | `Code.gs`의 `SECRET_TOKEN` 수정 → 새 버전으로 재배포 → 폰 ⚙ 설정에 새 토큰 입력 |
| **업로드 폴더 변경** | `Code.gs`의 `ROOT_FOLDER_ID` 수정 → 새 버전으로 재배포 → `authorize` 다시 실행 |
| **화면/아이콘 수정** | GitHub 저장소의 파일을 같은 이름으로 덮어쓰기(Add file → Upload files). 반영까지 1~2분 |
| **앱 이름 변경** | `manifest.webmanifest`의 `name`, `short_name` 수정 후 홈 화면 아이콘 재추가 |
| **아이콘 그림 변경** | PNG 4개를 같은 이름으로 교체 (192, 512, 512, 180px) 후 `sw.js`의 `CACHE` 숫자를 올리고(예: `v3`→`v4`), 홈 화면 아이콘 재추가 |

> 파일을 고쳤는데 폰에서 예전 화면이 보이면 페이지를 **새로고침**하세요. 그래도 같으면 `sw.js`의 `CACHE` 버전 숫자를 올려서 다시 올리면 됩니다.

## 10. 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| 홈 화면 아이콘이 주황색 **"G"** 글자 | `script.google.com` 주소로 추가한 경우. GitHub Pages 주소로 다시 추가하세요. |
| 아이콘을 바꿨는데 예전 그림 | 기존 아이콘을 삭제하고 새로 추가하세요. |

| 연결 테스트: `연결 실패` | ① URL 끝이 `/exec`인지 ② 배포 시 액세스 권한이 **모든 사용자**인지 ③ 폰이 인터넷에 연결되어 있는지 확인. URL을 PC 브라우저에서 열어 JSON이 나오는지도 확인해 보세요. |
| 연결 성공인데 폴더 오류 | 배포한 구글 계정이 해당 드라이브 폴더에 편집 권한이 없는 경우입니다. 폴더 ID도 확인하세요. |
| 올리기를 눌렀는데 안 올라감, `Wi‑Fi 연결을 기다리는 중` | Wi‑Fi에 연결되어 있지 않습니다. Wi‑Fi를 켜세요. |
| `네트워크 종류를 확인할 수 없어 대기 중` | 브라우저가 연결 종류를 알려주지 않는 환경입니다. 하단의 "확인할 수 없는 기기는 현재 네트워크로 업로드 허용"을 켜세요. |

| 오류: `용량 초과(40MB)` | 사진 한 장이 40MB를 넘습니다. 크기를 줄여서 올리세요. |
| 오류: `HTTP …` / `Failed to fetch` | 일시적 네트워크 문제이거나 Apps Script 일일 한도 초과입니다. 잠시 후 `오류 항목 재시도`를 누르세요. |
| 사진이 `중복건너뜀`으로 나오는데 실제로는 없음 | 이름과 용량이 같은 파일이 해당 월 폴더에 이미 있는 것입니다. 드라이브의 `YYYYMM월` 폴더를 확인하세요. 휴지통에 있는 파일은 중복으로 보지 않습니다. |

## 11. 한도와 비용

- **비용**: 개인 구글 계정·공개 GitHub 저장소 기준으로 **무료**입니다. `SECRET_TOKEN`은 요금과 무관한 비밀번호 역할의 문자열입니다.
- **구글 드라이브 용량**: 무료 15GB (지메일·구글 포토와 공유). 넘으면 용량 추가 구독이 필요합니다.
- **Apps Script 일일 한도**: 하루 실행 시간·호출 횟수에 제한이 있습니다. 한도를 넘으면 그날은 오류가 나지만 요금이 청구되지는 않으며, 다음 날 다시 사용할 수 있습니다. 사진이 매우 많다면 나눠서 올리세요.
- **사진 1장당**: 40MB 이하.
- **GitHub Pages**: 공개 저장소는 무료입니다. (비공개 저장소는 요금제에 따라 제한)

## 12. 보안 주의사항

1. **`Code.gs`는 공개 GitHub 저장소에 올리지 마세요.** 파일 안에 `SECRET_TOKEN`과 드라이브 폴더 ID가 들어 있습니다. 올리면 누구나 토큰을 볼 수 있고, 웹 앱 URL까지 알게 되면 내 드라이브 폴더에 사진을 올릴 수 있습니다. 보관이 필요하면 토큰 부분을 가짜 값으로 바꾼 사본을 올리세요.
2. 웹 앱이 "모든 사용자" 접근이라서 **웹 앱 URL과 토큰을 남에게 알려주지 마세요.** 토큰이 틀리면 서버가 요청을 거부하지만, 토큰이 노출되면 막을 수 없습니다.
3. 토큰이 노출됐다고 의심되면 즉시 `SECRET_TOKEN`을 바꾸고 → 새 버전으로 재배포 → 폰 ⚙ 설정에 새 토큰을 입력하세요. 필요하면 Apps Script **배포 관리**에서 기존 배포를 보관처리해 URL 자체를 무효화할 수도 있습니다.
4. 이 앱은 사진을 올리기만 합니다. 드라이브의 기존 파일을 삭제하거나 수정하지 않습니다. (같은 이름·다른 내용이면 새 이름으로 저장)
5. 구글 API 키 등 다른 비밀 값은 이 앱에서 사용하지 않습니다. 대화나 코드에 노출한 키가 있다면 Google Cloud 콘솔에서 폐기하세요.
